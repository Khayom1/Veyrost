Трёхфазная верификация: промпт, который превращает ИИ в рецензента

✓ Проверено и опубликовано: 2026-10-06 · VEYROST AI Lab

Большинство промптов дают правдоподобные ответы, которые разваливаются при проверке. Базовый промпт «Напиши функцию Python `longest_common_subsequence(a, b)`...» вернул обрезанный, нерабочий код без доказательств и обработки краевых случаев. Модель остановилась на середине бэктрекинга и посчитала задачу выполненной. Это проблема самоуверенности: модель не проверяет свою работу, потому что мы её об этом не просим.

Мы протестировали технику под названием Self-Consistent Chain of Verification with Adversarial Counterexample Generation. Она получила 88/100 и была одобрена. Вот как она работает и почему это важно.

Практический промпт

You are a senior software engineer and logic verifier. Solve the following problem using a three-phase process:

Problem: Write a Python function `longest_common_subsequence(a, b)` that returns the longest common subsequence of two strings. Then, prove that your function is correct for all inputs.

Phase 1: Generate three independent solutions using different algorithmic approaches (e.g., dynamic programming, recursion with memoization, and a greedy approach if possible). For each, provide the code and a brief explanation.

Phase 2: For each solution, perform a step-by-step verification of its logic. Identify any assumptions, potential off-by-one errors, or edge cases (e.g., empty strings, repeated characters, different lengths).

Phase 3: Adversarially test each solution by constructing at least three specific input pairs that could break it. For each, explain why the solution might fail and whether it actually does. Then, select the most robust solution and provide a final corrected version if needed. Finally, state your confidence level (0-100%) that the final function is correct for all possible inputs, and justify it.

Output your complete reasoning and final code.

Результаты теста

Базовый промпт выдал одно DP-решение, обрезанное на середине бэктрекинга — неполное, нерабочее, без верификации. Ни доказательств, ни краевых случаев, ни оценки уверенности. Модель предположила, что первый правдоподобный подход верен.

Протестированный промпт заставил модель вести себя иначе. Она сгенерировала три независимых решения: восходящее DP, рекурсию с мемоизацией и жадный алгоритм. Затем проверила каждое пошагово, выявив ошибки на единицу и краевые случаи — пустые строки, повторяющиеся символы. В фазе 3 она построила состязательные входные данные, призванные сломать каждое решение, и корректно определила, что жадный подход не работает для LCS (например, `a="abc"`, `b="acb"`). Она выбрала DP-решение, предоставила исправленную версию и указала уровень уверенности с обоснованием.

Почему это работает? Три механизма:

  • Многоперспективное рассуждение. Генерация трёх разных алгоритмических подходов заставляет модель исследовать пространство решений, а не цепляться за первую идею. Перекрёстная проверка между подходами выявляет ошибки, которые одна цепочка пропустила бы.
  • Явное состязательное тестирование. Просьба атаковать свои выводы вскрывает скрытые допущения. Провал жадного алгоритма на LCS — классическая ловушка, и модель поймала её только потому, что мы потребовали генерацию контрпримеров.
  • Оценка уверенности. Требование числового уровня уверенности с обоснованием снижает самоуверенность. Модель не может просто сказать «это верно» — она должна количественно оценить и защитить свою уверенность.

Результат — код, имитирующий строгое рецензирование и ред-тиминг. Это не просто лучший ответ — это проверяемый ответ. Для сложных логических и программных задач эта техника стабильно даёт более надёжные решения с меньшим числом скрытых допущений.

Используйте её, когда корректность важнее скорости. Накладные расходы оправданы, когда неправильный ответ стоит дороже медленного.
